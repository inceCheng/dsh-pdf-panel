# `lab/` — standalone harness for the lazy PDF viewer chunk

This directory is **not** part of the plugin build, its published package, or
`lib/`. It exists to drive `src/client/pdf/**` in a real browser without a DSH
host, so rendering, the PDF.js text layer, native selection, the right-click
menu, and cleanup can be verified end to end.

Everything here stays local to `lab/`:

| Path | Purpose |
| --- | --- |
| `build.mjs` | Bundles the real `src/client/pdf/index.tsx` chunk into `dist/bundle.js` and writes `dist/index.html`. Mirrors the plugin build's generated `dsh-pdf-assets` module (worker source + CMaps/standard-fonts/wasm base64 from the plugin's installed `pdfjs-dist`). React is bundled from this directory's own copy so the standalone page has a single React instance. |
| `entry.tsx` | Lab page entry: fetches a PDF, mounts `PdfPanel` with mock `PdfViewerLabels`, records `onPassageAction` calls on `window.__lab`, and exposes `window.__lab.unmount()` / `window.__lab.remount()` for cleanup checks. |
| `test.mjs` | Playwright test: generates a 3-page selectable-text PDF, serves `dist/` + the PDF on an ephemeral loopback port, drives system Google Chrome (`channel: 'chrome'`, no browser download), asserts behaviour, and writes screenshots. |
| `dist/` | Generated page (`index.html`, `bundle.js`); safe to delete. |
| `.build/` | Generated `pdf-assets.generated.ts`; safe to delete. |
| `samples/sample.pdf` | PDF regenerated by every test run from Chrome's print engine. |
| `screenshots/` | Latest screenshots from a successful `npm test` run. |
| `node_modules/` | Lab-only dependencies (`esbuild`, `playwright-core`, `react`, `react-dom`). |

## Requirements

- Node.js 22+
- Google Chrome installed at the system location (`playwright-core` launches it
  with `channel: 'chrome'`; nothing is downloaded)
- Network access on first run, only for `npm install`

## Run

```sh
cd lab
npm install        # esbuild, playwright-core, react, react-dom
npm test           # build + full Playwright run
```

`npm test` exits non-zero on any failed assertion and prints a `ok` / `FAIL`
line per check.

The page can also be opened manually after `node build.mjs` if `dist/` and the
sample PDF are served together (the test's built-in HTTP server does this):
`dist/index.html?w=<frame width>&src=<pdf path>`.

- `?w=` sets the simulated sidebar width (default 720 px).
- `?src=` selects the document URL (default `/sample.pdf`); the test uses
  `/invalid.pdf` for the failure-state check.
- The frame is 720×860 px by default, mimicking the right-sidebar tab body.

## What the test proves (latest run: 54 checks)

1. **Rendering** — document loads through the dedicated PDF.js worker, page
   count is reported, page 1 canvas has a device-pixel-ratio-aware bitmap,
   page 3 stays lazily unrendered until scrolled near, and the toolbar shows
   `第 1 / 3 页`.
2. **Native text layer** — mouse drag over the PDF.js `TextLayerBuilder`
   produces a real `window.getSelection().toString()` that includes the
   `PDFMARKER` sentence baked into the sample PDF.
3. **Right-click menu** — right-click on the selection opens
   `[data-dsh-pdf-menu]` with `解读` / `翻译` / `复制`; the menu carries the
   selection via `data-selection-text`; clicking `解读` calls
   `onPassageAction('explain', <selected passage>)` exactly once and closes the
   menu; `翻译` delivers `translate`; `复制` writes the passage to the
   clipboard and shows `已复制`; a right-click without a selection shows no
   menu; Escape closes the menu.
4. **Cross-page selection** — one drag from the last line of page 1 into
   page 2 yields a single selection containing both pages' text, and the menu
   opens with that full passage.
5. **Zoom, navigation, fit-width** — zoom-in increases the percentage and
   leaves fit mode, fit-width restores it, next-page navigation updates the
   toolbar to `第 2 / 3 页`, and the last page then renders.
6. **Theme** — the viewer follows `prefers-color-scheme: dark`, and
   `<html data-ds-theme-source="dark|light">` overrides the OS preference in
   both directions; the dark selection menu has a dark surface with readable
   light text and the text layer stays usable.
7. **Narrow sidebar (~500 px)** — the toolbar does not overflow at 460 px, the
   fit-width zoom adapts (53%), selection works, and the selection menu is
   clamped inside the viewer bounds.
8. **Failure + retry** — an invalid PDF renders the localized
   `PDF 加载失败：…` message with a `重试` button; retry tears down the failed
   worker (terminate + blob URL revoke) and starts a fresh one without unhandled
   rejections.
9. **Worker-only parsing** — with `window.Worker` patched to throw, the viewer
   reports the failure and never renders a page on the main thread.
10. **Lifecycle** — a probe counts worker creation/termination and Blob URL
    revocation: re-mounting (tab switch away/back) creates a new worker and
    cleans up the old one; passing new bytes without unmounting (opening another
    PDF) reloads the document and releases the previous worker; unmount
    terminates the worker, revokes its Blob URL, removes the viewer DOM, and
    raises no unhandled promise rejections.

## Notes

- The harness bundles React inside `dist/bundle.js`; the plugin's own build keeps
  React external because the DSH shell provides it.
- The generated `dsh-pdf-assets` module duplicates the plugin build's logic on
  purpose: the lab must exercise the exact worker/CMap/font/wasm resources the
  real chunk embeds.
- The sample PDF is produced with Playwright's `page.pdf()` (Chrome print
  engine), so the text is real selectable text, not a scanned image.
